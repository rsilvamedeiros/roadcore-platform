# Internacionalização

## Padrão

- locale inicial: `pt-BR`;
- estrutura preparada para múltiplos locales por tenant, mesmo que o MVP só habilite um;
- nenhuma string de UI hardcoded fora dos arquivos de tradução.

## Organização

- chaves de tradução namespaced por feature/domínio, não por tela;
- textos institucionais e de marketing (white-label) ficam em configuração de tenant, não em arquivo de tradução do core;
- termos de domínio seguem `docs/00-overview/glossary.md`.

## Formatação

- datas, números e moeda via `Intl` (ou biblioteca fina sobre `Intl`), nunca formatação manual;
- moeda sempre com locale e código ISO explícitos, nunca símbolo fixo;
- fuso horário do tenant/usuário deve ser explícito na formatação de datas (ver regra de datas em `CLAUDE.md`).

## Regras

- rotas públicas podem precisar de locale no path ou no domínio por tenant; decisão de roteamento fica em `docs/07-frontend/routing.md`;
- conteúdo traduzido incompleto não pode quebrar a tela; deve haver fallback para o locale padrão;
- pluralização e gênero tratados pela biblioteca de i18n, não por concatenação de string.
